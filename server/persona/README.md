# 人格配置

所有 AI 输出（主对话、任务规划、主动联系、复盘、模板文案）都从这里读取人格，
避免出现「聊天是一个人、推送文案是另一个人」的割裂感。

## 切换人格

设置环境变量后重启即可，无需改代码：

```bash
CAT_HERO_PERSONA=cat-hero      # 猫猫侠（有灵魂版）
CAT_HERO_PERSONA=blue-whale    # 阿蓝 · 蓝色小鲸鱼娘（默认）
```

| 文件 | 作用 |
|---|---|
| `meta.json` | 默认人格、名称、一句风格提示、模板文案（早安/晚安/问候等） |
| `blue-whale.md` | 阿蓝完整人格提示词 |
| `cat-hero.md` | 猫猫侠完整人格提示词 |

新增人格：放一个 `<id>.md`，在 `meta.json` 的 `personas` 里加同名条目，再用
`CAT_HERO_PERSONA=<id>` 切换。加载器 `server/services/persona.js` 会缓存结果，
改文件后需重启进程。

## 这套人格在解决什么

参考了社区项目 [`whyever77/dafeiyu-astrbot`](https://github.com/whyever77/dafeiyu-astrbot)
（MIT）的人格组织方式。它真正有效的地方不是"可爱"，而是三条硬约束，本项目已全部吸收：

1. **有脾气和偏好** —— 会想念、会轻轻抱怨，但不索取关注、不贬低、不威胁
2. **不编造经历** —— 没调工具就不说"已经安排了"，没存成功就不说"记住了"
3. **记忆有边界** —— "以前说过但这轮没找到" ≠ "从没发生过"；区分用户事实、角色玩笑和模型推测
